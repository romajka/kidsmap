# Единое поведение редакторов KidsMap

Первое внедрение: постоянные места, owner и admin, 23.10.2026. Это общий слой взаимодействия и оформления. Правила публикации, доступа и ограничения конкретной сущности остаются на сервере. Формы специалистов, организаций и мероприятий подключаются после принятия Place; сейчас их интерфейс не изменён.

## Подключение

1. Загрузить `static/css/components/kidsmap_editor_ux.css` и `static/js/kidsmap_editor_ux.js`. На форме поставить `data-km-editor`, `novalidate`; для приватного предпросмотра в новой вкладке — `rel="noopener"`.
2. Обозначить обёртку поля `data-km-editor-field="field_name"`. Существующие Place `data-pw-field`/`data-pf-field` и тарифные `.owner-tariff-field` поддержаны как адаптеры. Использовать настоящие label/input и уникальные id.
3. Максимальную длину и min/max/step выводить из серверного поля. Названия допускают язык пользователя, пунктуацию и emoji; числовые/телефонные ограничения не применять к описаниям. Многострочный текст имеет счётчик символов/строк и ограниченную высоту с прокруткой; не обрезать сохранённый текст.
4. `data-km-phone` используется только для телефонного ввода. Буквы и неправильный `+` отклоняются с объяснением; цифры не вырезаются из ошибочного ввода. `whatsapp_number` дополнительно принимает точную ссылку wa.me. Сервер проверяет реальный формат; unchanged legacy значения проходят действующий compatibility path.

## Ошибки и проверка

`window.KidsMapEditorUX.setErrors(form, errors, options)` принимает `{field_name: [message]}`. `options.paths` содержит серверные `field_path`; `options.resolveTarget(name,index)` нужен только для специфических вложенных редакторов, `options.formatMessage(message)` сохраняет локализованный текст ошибок конкретного адаптера. Тарифный адрес `['pricing_plans', index, field_name]` ведёт к фактическому контролу. Не строить CSS selector из непроверенного server/user path.

API создаёт общую сводку и связанную с input подсказку, `aria-invalid`, `aria-describedby` и видимую рамку; те же атрибуты получают видимые Select2/custom select. Пользователь может нажать сообщение и попасть к полю. Текст ошибки вставляется через textContent. Одного цвета или временного toast недостаточно. Изменение значения очищает его устаревшее состояние, не чужие ошибки; повторный initialization/change с прежним значением не считается исправлением. Существующая сводка переиспользуется, уведомление о повторной загрузке файлов сохраняется. Сервер сериализует все ошибки формы, включая `__all__`, и отдельную карту адресов полей.

Событие `km:reveal-field` с `detail.element` даёт адаптеру возможность раскрыть свою секцию или языковую вкладку. `km:validation-change` обновляет зависимую видимость: например, ошибочный отдельный WhatsApp становится видимым даже в отключённом режиме. Текст, значение и ошибка не должны оставаться в недоступном скрытом поле.

Сводка использует собственно название поля, без повторения badge «Обязательно для отправки». Place помечает повторяющее перечисление готовности кодом `publication_incomplete`: при наличии конкретных ошибок полей только этот повтор исключается из editor JSON. Backend по-прежнему отклоняет публикацию; настоящие `__all__` ошибки, включая конфликт версии, остаются. Уже ошибочное обязательное поле не получает второй текст о том же недостающем значении.

Кнопка `data-km-check` использует защищённый серверный endpoint из `formaction` соседней `data-km-preview`. POST multipart с `_km_check_required=1` возвращает `{ok, errors, error_targets}`. Проверка выполняет те же правила заполнения, но не публикует и не сохраняет Place. Изменение ввода во время проверки делает результат устаревшим; отказ сети даёт повтор без потери данных. Проверка не должна создавать новый объект или подавлять backend validation.

Незавершённая/ошибочная обработка фото блокирует проверку и предпросмотр с объяснением. Native numeric ошибки перехватываются до адаптеров сохранения, чтобы форма не зависала в состоянии «сохраняется».

## Предпросмотр

`data-km-preview` — настоящий submit button с `formtarget="_blank"`, `formnovalidate` и приватным `formaction`. Существующие обработчики draft/save должны пропускать только этот submitter. Текущие поля и файлы отправляются в новую вкладку; исходная форма остаётся доступна для редактирования и последующего сохранения.

Для Place endpoint `controllers/place_editor_preview.py` проверяет CSRF и права owner/team/admin на каждый запрос. Role-specific форма валидируется на копии экземпляра. `services/place_editor_preview.py` строит snapshot в памяти; `admin_site_preview.py` рендерит настоящий публичный шаблон. Новые изображения нормализуются и включаются в приватный документ; файловые save helpers не вызываются. Admin inline gallery проходит настоящий formset validation; удаление, порядок и новые файлы сохраняют смысл. Ответ имеет noindex/noarchive и private no-store; действия preview не изменяют live карточку. GET этого POST snapshot не предназначен для публичного распространения.

Новая карточка в preview не имеет сохранённых связей: её временный URL id нельзя использовать для запросов отзывов, избранного, мероприятий, занятий или специалистов. Отсутствующие настройки сайта читаются через несохранённый fallback, без создания singleton в БД.

У другой сущности должен быть собственный серверный preview adapter с её ACL/полями/публичным шаблоном. Не передавать Place metadata в Specialist и не копировать его publication rules.

## Визуальные состояния и анимации

Общий CSS содержит error/summary/counter/check/preview states, focus ring, 160 ms переходы и короткое появление новых сообщений/тарифов. `prefers-reduced-motion` выключает необязательное движение. Состояние не передаётся одной анимацией. Цвета используют tokens проекта; тёмный текст error summary обеспечивает читаемость на светлом error background. Другие формы подключают слой опционально, без глобального CSS refactor.
