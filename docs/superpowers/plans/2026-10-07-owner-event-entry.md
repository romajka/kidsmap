## Решение

Улучшить существующую форму с **тремя этапами**, её controller и действия в текущем кабинете. Второй wizard, новая модель черновика или обход `event_domain` не нужны.

1. **Основное и дата:** организатор, название AZ, категория, начало/окончание Asia/Baku, возраст, цена, телефон события, описание AZ.
2. **Формат и место:** доступные клавиатурой очно/онлайн; площадка KidsMap отдельно от организатора либо собственный адрес; необязательная карта.
3. **Фото и предпросмотр:** одна главная фотография, комментарий модератору, согласованный с сервером список незаполненного, отправка на модерацию.

Черновик доступен на каждом этапе. Переход вперёд позволяет увидеть следующие блоки без полного заполнения требований публикации. Сохранение и отправка проверяются сервером. Ошибки имеют ссылки на нужный этап и фокусируют видимый контрол, включая `altInput` существующего date/time picker.

## Правила, которые сохраняем

| Область | Текущий контракт | Отражение в интерфейсе |
|---|---|---|
| Организатор | Ровно одна действующая организация текущего владельца **или** действующий Specialist с `verified_person_user` текущего пользователя и `person_verified_at` | Объяснить доступность. Не называть организацию «проверенной» и не обещать качество услуг. Автор предложения специалиста не становится организатором |
| Редактирование | Через кабинет редактируются draft/rejected. Организатора уже созданного Event нельзя заменить | Показывать закреплённого организатора без редактируемого select. Pending/published остаются ограничены |
| Площадка | Неудалённые активные собственные места или опубликованные доступные места | Показывать название и адрес. Выбор чужой публичной площадки не передаёт права и не меняет организатора |
| Черновик | Организатор; категория обязательна на уровне БД. Даты обе пустые либо оба момента с корректным интервалом; заполненные значения валидируются | Исправить form validation категории, чтобы вместо IntegrityError показывать ошибку поля. Не делать категорию nullable и не требовать все поля публикации |
| Отправка | Название/описание AZ, категория, даты, возраст (0 допустим), цена, телефон, фото; физический адрес для очного события; корректные значения и актуальные даты | Список требований берётся из существующего owner-контракта; не расширять/смягчать его. Исправление ошибок не означает публикацию |
| Дата и время | Asia/Baku, aware datetime, окончание позже начала; окончание следующего дня требует явной даты; неизменённые секунды/microseconds существующего интервала сохраняются | Показывать полный интервал и длительность. «Окончание в другой день» открывает дату; не угадывать перенос на следующий день |
| Формат | Значения `physical`/`online`; сервер удаляет физические поля онлайн-события; утверждённый формат защищён | Native radio + fieldset/legend; в браузере сохранять введённый очный адрес при переключении до сохранения. На повторном открытии учитывать реальные сохранённые поля |
| Место публикации | Public использует immutable `venue_snapshot`, не текущую изменённую карточку Place | При выборе площадки показывать её фактический адрес; для иного адреса явно выбрать собственный. Не обещать автоматическое изменение опубликованной географии |
| Карта | Координаты необязательны для owner Event | Сообщить о сбое карты; сохранить адрес и продолжение. Не переносить требования постоянного Place на Event |
| Телефон | Отправка требует валидный телефон события; пустой телефон не проходит `clean_phone`, даже при телефоне площадки | Убрать противоречивое обещание наследования. Кнопка «Использовать телефон площадки» явно заполняет телефон события. Не менять правила валидатора |
| Фото | Existing normalizer: исходник до 15 MiB, 50 MP/12000 px, JPG/PNG/WEBP/HEIF; результат до 2 MiB, ошибки HEIF при недоступном codec | Использовать действующую конфигурацию для клиентских ограничений и текста вместо отдельных 2 MB/JPG-only констант. Не менять обработчик/лимиты сервера и не добавлять галерею |
| Версия | `expected_updated_at`, актуальные права и данные повторно проверяются в transaction; stale_version не перезаписывает запись | Явный код ошибки, сохранённый ввод, сравнение с актуальной версией. Не подставлять новый token и не повторять POST автоматически |
| Отмена/перенос | Существующие `cancel_event`/`reschedule_event`, текущий организатор, reason, version; перенос только ещё не начавшегося и не отменённого Event | Отдельное действие с последствиями и подтверждением; отмена не удаляет Event. Начавшееся/прошедшее событие требует нового ID |
| Языки | Эта owner-форма сохраняет `name_az`/`description_az`; язык UI не создаёт перевод | Метки AZ на RU/AZ/EN. Не добавлять автоматические переводы, новые поля/права или другой редактор |

## Конкретный scope реализации после согласования

### 1. Форма, навигация, понятные состояния

- Существующие 3 кнопки этапов и мобильную навигацию привести к одной логике: активный этап, незаполненные поля, заголовок/фокус, возврат без потери ввода.
- Организатор: реальный список по прежнему queryset, отсутствие доступных вариантов, ссылка прямо на уже существующее создание организации, пояснение подтверждения связи с Specialist. Никаких новых прав автора предложения.
- На редактировании показать закреплённого организатора; изменение через подменённый POST по-прежнему отклоняет сервис.
- `fieldset`/native radio для формата и типа адреса; `checked`, `disabled`, `hidden`, описания и ошибки доступны через клавиатуру и accessibility tree.
- Ввод возраста 0 отличать от пустого; цена остаётся текстом, телефон относится к событию, не владельцу/площадке автоматически. Описание AZ сохраняет текущий максимум 300 символов.
- Отдельные состояния недоступной площадки и карты. Не подменять площадку/адрес и не менять серверный snapshot.
- Требования черновика и отправки показывать отдельно. Не давать проценты готовности по произвольному числу полей.
- Удалить из owner-копирайта неподкреплённые обещания качества «подтверждённого» профиля, встроенной регистрации и отправки ссылки участникам. Внешняя запись по контакту допустима как условие участия. Убрать жёсткое обещание срока проверки без данных действующего SLA.

### 2. Сохранение, ошибки, восстановление

- В OwnerEventForm валидировать обязательную категорию для draft; неполную пару дат возвращать как адресуемую ошибку. Исправляется отображение действующих ограничений, не ограничения domain/БД.
- Передавать из controller структурированный `stale_version` в контекст, не распознавать конфликт по словам перевода. Существующий HTTP rendering можно сохранить.
- Состояния: «ещё не сохранено», «есть изменения», «сохранение», «черновик сохранён» только после успешного ответа, «не удалось сохранить»/конфликт. Не обещать server autosave.
- Локальное восстановление текущей формы: ключ `actor + entity/create + schema`, сохранённая base version; allowlist всех её скалярных полей, в том числе format, venue choice, related_place, region, coordinates, note, текущий этап. Не хранить файл/CSRF/документы/response HTML.
- Новые карточки и редактирование различать; при несовпадении версии предложить сравнение, а не накладывать старый ввод поверх серверных данных. Прочие аккаунты не получают текст предыдущего пользователя. Прежние ключи без actor не восстанавливать.
- Не очищать локальную копию до ответа сервера; очищать после подтверждённого сохранения/отправки/явного отказа пользователя от восстановления. На network/validation/stale ошибке ввод сохраняется. Файл после обновления нужно выбрать заново.
- Ошибка файла согласована с действующей image pipeline; остальные поля не теряются. Сохраняем одну главную фотографию, существующие дополнительные фотографии не затрагиваем.

### 3. Отмена и перенос

- Добавить тонкие owner POST adapters и действия в существующем кабинете поверх `event_domain.cancel_event`/`reschedule_event`; CSRF, feature gate, свежая версия, current organizer ACL.
- На странице управления показывать текущий публичный интервал/формат/площадку, причину и последствия. Перенос принимает новый полный интервал Asia/Baku. Показать запрет для начавшегося/отменённого события по текущим сервисам.
- Кнопки подтверждения блокируются на время запроса; повтор старого POST остаётся конфликтом сервера. После результата обновить состояние из ответа. Чужие/устаревшие права и иной редактор не обходятся UI.
- Не открывать обычное редактирование опубликованного контента; не менять организатора, snapshot, формат, фото или публикацию. Не обещать рассылку, возвраты денег или регистрацию участников.

### 4. Предполагаемые файлы

Основные: `src/catalog/forms.py` (только OwnerEventForm), `src/catalog/controllers/owner_events_controller.py`, `src/catalog/views.py` (owner Event adapters), `src/catalog/urls.py` (owner cancel/reschedule), `src/catalog/templates/pages/owner_event_form.html`, `static/js/owner_event_form.js`, `static/css/pages/owner_event.css`.

Точечно: существующие owner dashboard template/row presentation для кнопок и состояния, общий map picker только через event-specific option/attribute; `locale/{ru,az,en}/LC_MESSAGES/django.po` для изменённых Event строк. При реализации сначала trace callers и читать diff этих уже изменённых файлов. Общие строки, используемые на других страницах, проверять у всех найденных потребителей. Existing date/time/image helpers использовать без изменения их бизнес-правил.

Тесты: отдельный owner Event regression module и нужные существующие Event tests. `event_domain`, Event model, migrations, staff/organization/specialist/publication policies, organization join/detach, Place/Activity/Group/PricingPlan и галерея — без изменения правил.
