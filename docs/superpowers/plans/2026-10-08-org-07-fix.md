# ORG-07 — безопасная форма приглашения сотрудников

Scope согласован последовательным поручением пользователя «дальше», только ORG-07.

Свежая проверка на HEAD 2da9d33a / dirty WORKTREE подтвердила GET с query keys csrfmiddlewaretoken/email/role/scope. Запрос перехвачен и прерван до сервера; значения не записаны. У формы отсутствуют method/action. API принимает только JSON POST и проверяет CSRF, владельца, scope и актуальность приглашения.

Выбран разрешённый finding вариант: явная недоступность приглашения без работающего JS. Не добавлять второй server transport.

1. HTML: method=post/action на существующий team API; email/role/scope/branch checkbox/submit исходно disabled. Объяснение RU/AZ/EN видимо до инициализации, в том числе при ошибке загрузки скрипта.
2. JS: после регистрации submit-handler включить только помеченные controls и скрыть объяснение. POST/fetch и canonical invite остаются прежними.
3. До изменения создать RED regression для server-rendered no-JS состояния. Затем GREEN и настоящая браузерная проверка no-JS, blocked script, JS, клавиатуры, POST, отказа, повторов и конфликтов.
4. Проверить RU/AZ/EN × 360/390/768/1440; сохранить PC/mobile screenshots и local diff относительно входного WORKTREE. Зафиксировать runtime source hashes и сохранность прежних файлов/синтетических данных.

Не трогать права, модели, canonical join/confirm/detach, публикацию, CSS или ORG-08 (reset/list/loading). Без внешнего email, production, commit/push/deploy. Server-only проверки stale ownership/concurrent acceptance не выдавать за браузерные.
