# Как KidsMap ведёт детскую афишу Баку

[Полный промпт редактора и проверяющих агентов](event-calendar-prompt.md) установлен в действующем таймере. При запуске вручную используются та же очередь, те же правила публикации и тот же журнал.

Владелец KidsMap разрешил публиковать проверенные сеансы по расписанию через рабочую админку и обновлять их при переносе и отмене. Работу ведёт одна автоматизация Codex в чате афиши. Доступ к почте, изменение прав, кода или конфигурации сайта для этого процесса не требуются.

## Сверка опубликованного и поиск на полгода

Каждый запуск начинай со сверки живой афиши, списка текущих и будущих публикаций в админке и журнала по ID. Перепроверь отмены, переносы, место, цены, регистрацию и обложки по актуальному источнику. Ищи новые семейные события помесячно на шесть месяцев вперёд. Для этой расширенной проверки готовь локальный список исправлений, оригинальные официальные изображения с правом публикации и ссылки на подтверждения. Покажи охват и остаток. Прежний редакционный выпуск на 60 дней веди по правилам ниже.

В каждом выпуске просматривать несколько независимых площадок и продолжать поиск после первой удачной публикации. Сверять очереди театров, музеев, городских фестивалей и детских студий. Перед поиском открыть гостевые подборки выходных и бесплатного входа. В каждой неделе посчитать отдельно разные программы и сеансы. Если предложений мало или почти все сеансы у одной постановки, сначала проверить недостающий район, возраст и формат. В журнале различать впервые найденную программу, дополнительный показ, новые сведения для уже известного кандидата, архив, недоступный источник и календарь без объявленных дат. Для незавершённой проверки указать конкретный вопрос и куда вернуться. [Примеры из сверки 27 ноября](../reports/afisha-source-coverage-2026-11-27.md)

Для каждой программы проверить официальный Instagram организатора или площадки, если он есть. Найти аккаунт через официальный сайт или ссылку организатора. Открыть пост, пролистать карусель, прочитать подпись к Reels, проверить актуальные Stories и Highlights на изменения. При наличии посмотреть официальные Facebook и Telegram. В журнал записать прямую ссылку на публикацию, дату её выхода и время сверки по Баку. Для исчезающей истории записать доступную ссылку, аккаунт и содержание объявления. Пример официального профиля — [Instagram Национального музея искусств](https://www.instagram.com/nationalartmuseum.az/).

Если источники расходятся, сопоставить один показ по площадке, дате и языку, сохранить обе ссылки и спорные значения. Перенос проверить по свежему объявлению организатора, цену — в кассе выбранного сеанса. Если публикация закрыта или исчезла, отметить дату и ограничение доступа и проверить другой официальный канал. При нерешённом обязательном факте новый сеанс оставить в очереди проверки, у существующего сохранить ID и передать расхождение по действующему порядку.

После постера пройти каждую доступную галерею этой постановки, включая все слайды официальной карусели. Для каждого альбома записать источник и результат просмотра. По программе отдельно посчитать найденные кадры, уникальные оригиналы, загрузки, подтверждённые на гостевой карточке, и кадры в ожидании с причиной. Для публикации каждого файла сохранить автора, основание использования и требуемый кредит. Повторные размещения одного кадра по сеансам учитывать отдельно.

Владелец разрешил создавать под рабочим аккаунтом `roma` внутреннюю карточку любого подтверждённого организатора, если поиск по всем статусам и вариантам написания не выявил дубля. Сохранять ID и ссылку в журнале, затем привязывать организацию к мероприятию. Площадку сверять отдельно. Для площади без карточки места можно указать проверенный адрес и координаты входа прямо в событии. Для бесплатного входа без записи можно указать публичный справочный телефон принимающей стороны, пояснив условия посещения.

Указывать ссылку на покупку конкретного события, если её дал организатор или редактор уже проверил её соответствие этому показу. В поле способа записи KidsMap выбрать ссылку. В описании назвать первоисточник и продавца билетов, сохраняя адрес источника в журнале. Если у организатора есть собственная страница события с кнопкой покупки, можно дать её как страницу организатора. Не выдавать кассовую ссылку за подтверждение наличия мест.

Автоматический сбор с iTicket включать только в пределах разрешения самого iTicket. До этого использовать афиши организаторов, а на iTicket направлять посетителей по известным билетным ссылкам. Не собирать каталог iTicket через поисковые сниппеты, внутренние запросы или копии на других сайтах. Текст KidsMap писать самостоятельно. В «Главное фото» загружать официальный рекламный постер или промобаннер конкретной программы с читаемым названием либо фирменной надписью события и подтверждённым правом на использование файла. Сверить напечатанные реквизиты с сеансом. Сценические и репортажные кадры помещать в дополнительные фото. [Правила iTicket](https://iticket.az/ru/page/rules)

## Правила поиска для всей афиши

В [админке мероприятий](https://admin.kidsmap.az/admin/catalog/event/) откройте «Инструкция редактора афиши». Памятка доступна в списке, при добавлении и при редактировании события. Те же правила входят в «ИИ-промпт для афиши».

Эти правила действуют для каждой опубликованной записи, включая архив, и для каждого нового сеанса. Дата, место, язык, возраст, билет и статус берутся из самой записи. Редактор заполняет их один раз. Сайт использует эти же сведения в карточке, заголовке для поиска и разметке Event.

| Что ищет родитель | Какая страница отвечает | Что на ней должно быть |
|---|---|---|
| «Детская афиша Баку», «Bakıda uşaqlar üçün tədbirlər», «kids’ events in Baku» | Основная афиша соответствующего языка | Ближайшие варианты с датами, постоянная иллюстрация раздела и ссылки на карточки. Для общего «куда сходить с ребёнком» родительский гид связывает места с календарём событий. |
| «Что есть для детей сегодня», «Bakıda bu həftəsonu uşaqlarla hara getmək olar?», «family events in Baku this weekend» | Соответствующая подборка на сегодня или выходные | Актуальные сеансы, местные даты и ссылки на них. Индексируемые подборки имеют собственный адрес. Пустые и почти одинаковые комбинации фильтров не требуют дополнительных страниц. |
| Название постановки, площадка или дата | Страница отдельного сеанса | Название, подтверждённая площадка и город либо онлайн-формат, местные дата и время, язык выступления, возраст, цена и способ записи по имеющимся сведениям. При нескольких датах одной подтверждённой постановки — переход к другим сеансам. |

**При создании и обновлении.** Публикуй подтверждённое расписание, как только оно доступно в источнике. Заполняй названия и описания на AZ/RU/EN. Ссылку на первоисточник постановки сохраняй отдельно от ссылки покупки. Если касса даёт ссылку на выбранный сеанс, используй её. Для текущего представления выбирай официальный постер, для общей афиши — иллюстрацию раздела. Подтверждённое «от 5 ₼», единый билет 5 ₼, бесплатный вход и неизвестная стоимость должны различаться во всех трёх версиях.

**Повтор, перенос, архив.** У отдельно бронируемого сеанса свой постоянный адрес. Сверяй название, источник постановки, организатора и площадку: два театра могут показывать разные версии одной сказки. При переносе или отмене обновляй существующую запись и её статус. Для исправления старой карточки работай с тем же сеансом. Дату фактической проверки источника сохраняй в журнале. Дата изменения записи показывает, когда редактировались данные на сайте.

**Проверка результата.** Переход из афиши открывает нужный сеанс на выбранном языке. Заголовок вкладки, краткая сводка, цена, постер, место и ссылка на билет описывают один и тот же показ. Для старой записи виден её статус. В Search Console отдельно сверяй доступность опубликованного URL, попадание в индекс до спектакля и показы по названию. Для общих запросов смотри показы и клики основной афиши и подборок по языкам. Google самостоятельно определяет время обхода, позиции и оформление результата. Для ссылки в ИИ-обзоре страница должна попасть в индекс и допускать показ фрагмента. Азербайджан отсутствует в списке регионов специальной выдачи Google по мероприятиям. Для Баку отслеживай обычные поисковые показы и переходы на конкретные страницы. [Документация Google по событиям](https://developers.google.com/search/docs/appearance/structured-data/event) · [Обход и индексирование](https://developers.google.com/search/docs/crawling-indexing/ask-google-to-recrawl) · [ИИ-функции в поиске](https://developers.google.com/search/docs/appearance/ai-features)

### Как писать для семьи

Сначала назвать язык конкретного сеанса по правилу ниже. Сразу за ним дать одну проверенную деталь, ради которой семья выберет программу. Для спектакля это может быть сценический приём, для занятия — вещь, которую ребёнок сделает своими руками, для выставки — предмет, который можно рассмотреть. Если подробностей мало, выбрать самую конкретную из подтверждённых. Естественно вписать название или поисковую фразу на языке страницы и закончить понятным действием по этому сеансу. Разные постановки заслуживают разных описаний. У повторного показа той же программы менять только подтверждённые отличия, например состав, язык или часы.

Условные примеры формы анонса. Детали для настоящей карточки взять из её источника.

- «Спектакль идёт на русском. В театре теней за одним экраном на глазах у детей вырастает целый бумажный город. Выберите дневной или вечерний показ в кассе театра».
- «Занятие проходит на азербайджанском. На мастер-классе по керамике в Баку ребёнок слепит чашку и украсит её узором. Для записи выберите занятие в форме студии».

## Каждый запуск

Для очного сеанса сначала выбрать существующую площадку. В форме район выбирается из списка по региону. При ручном заполнении координат события форма принимает шесть знаков после запятой. В журнале сохранить исходную точность источника и отдельно значения для формы. После повторного открытия сверить адрес и точку на карте.

При запуске проверь актуальную сессию рабочего профиля, открыв список мероприятий на админском домене. Старая вкладка входа может остаться открытой после авторизации в другой вкладке. Организатор Музыкального театра Баку уже создан (ID 2), его площадка — ID 464. Перед записью сверять названия. На живой форме после открытия сохранённого события подтягиваются координаты площадки с семью знаками. Если браузер или сервер отвергает точность, проверь привязку площадки и адрес, оставь ручные координаты пустыми для штатного наследования и повторно сохрани черновик. Убедись, что форма приняла изменения. Публичную видимость подтверждают гостевая страница на основном домене и список афиши. Статус в админке подтверждает только этап публикации.

1. Открыть журнал `var/event-calendar/sessions.json` в основном рабочем каталоге KidsMap. Проверить изменения и отмены сначала у ближайших сеансов, затем искать новые в ближайшие 60 дней. Сохранять причину, если конкретный источник был недоступен.
2. Когда редактор просит сверить конкретное событие iTicket, открой его билетную карточку в браузере сам. Выбери нужную дату и время, сохрани локальный скриншот расписания и ссылку открытого сеанса. Если строка показывает «от», проверь доступные ценовые категории на схеме зала без выбора мест. Приложенный редактором скриншот также подходит, если видны нужный сеанс и его условия. При повторном запуске проверь записи с неизвестной ценой и обнови их по прежнему ID. Сопоставь постановку, площадку, дату и часы. Внеси все видимые факты: цену, валюту, возраст, язык, начало и окончание. У iTicket сверяй цену по строке конкретного сеанса, даже если в шапке или в общем списке событий показана сумма без «от». Пометку «от», «-dan/-dən» или «from» сохраняй как нижнюю границу. Если подтверждён полный диапазон тарифа для этого сеанса, запиши обе границы и условия тарифов. Когда известна только нижняя граница, оставь верхнюю пустой. Используй фиксированную цену только при подтверждённом едином тарифе для сеанса. Стоимость отдельного места и цены только оставшихся в продаже мест не определяют полный тариф сеанса. Перепроверь записи с «уточнить», сохрани источник и дату. Подтверждённую цену проверь в ценовом поле и в публичной афише. Для каждого сеанса проверить дату, местное время начала и окончания, организатора, площадку, адрес и ссылку для записи. Сохранять ссылку на источник для изменчивых сведений, включая цену, язык и возраст. Цену «от» вносить как «от». При отсутствии цены можно указать «уточнить». Возраст для отдельного билета и язык страницы не заменяют возраст аудитории и язык выступления. Начинать описания AZ/RU/EN с языка конкретного сеанса. Для спектаклей и занятий с речью публиковать сеанс после подтверждения языка детской программы. При нескольких языках перечислить все подтверждённые. Для самостоятельной выставки указывать известные условия языкового сопровождения. Проверить видимость в списке афиши и на странице сеанса. Остальные неподтверждённые необязательные поля оставлять пустыми.
3. Вести одну строку на реальный сеанс. Прежде всего сопоставлять по идентификатору сеанса у источника или ранее сохранённому ID KidsMap, затем по организатору, площадке, названию и времени. Страницы AZ, RU и EN одного сеанса относятся к одной записи. Для явного переноса сохранить исходный ключ и обновить ту же запись. Совпадение названия у разных театров само по себе ничего не доказывает.
4. Проверить дубли в рабочей админке среди всех доступных статусов, а также журнал текущего запуска. При недоступной проверке, неясном совпадении или отсутствии обязательного факта сохранить кандидата локально и продолжить с другими. Сопоставить именно организатора, отдельно указать площадку. Для главного изображения визуально проверить рекламный плакат текущей постановки. Общий постер допустим для сеансов, которым соответствуют напечатанные на нём сведения. Фото площадки допустимо как практический ориентир и учитывается отдельно от фотографий программы. Галереи только из общих фасадов оставлять в очереди поиска материалов постановки. При отсутствии обложки сохранять источник в журнале, новый сеанс оставлять в черновиках. У опубликованных сеансов отмечать требуемую замену и проверять очередь при каждом запуске.
5. Заполнять AZ, RU, EN. Публиковать готовый сеанс через обычную форму мероприятия. Перед сохранением повторить проверку совпадений. После сохранения заново открыть запись и публичную страницу, проверить сеанс, цену, ссылку записи и три языка. Зафиксировать ID, URL и результат. После прерывания сначала сверить состояние сайта. Не повторять создание при неизвестном результате.
6. При подтверждённом переносе или отмене использовать соответствующее действие для ранее сопоставленного сеанса. Если билеты распроданы, сохранить сам сеанс, пометить доступность в поддерживаемом интерфейсе и убрать устаревшее обещание покупки. Исчезновение страницы или ошибка связи требуют перепроверки. После окончания проверить уход сеанса из предстоящих. Сохранять журнал и историю события.
7. Обновлять журнал после каждого значимого изменения, заменяя файл атомарно. Не запускать второго редактора одновременно.
