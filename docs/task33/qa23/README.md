# Stage 23 synthetic R1 PostgreSQL rehearsal

`rehearsal.py` imports the unchanged `qa04/run.py` and prepends `bridge/commands.py` to the clean child environment. Use only `--mode probe` with a fresh `/tmp` output directory through the Linux mirror. The standard QA04 launcher still owns one network-none, no-port PostgreSQL 17 container with tmpfs PGDATA and a private Unix socket. The bridge locates that exact container by nonce label, name, running state, socket mount, network and tmpfs before calling native PostgreSQL tools.

The bridge first runs QA04 discovery, Django checks, migrations and query probe. On the disposable base DB it compares row-level digests for Place, PricingPlan, PlacePhoto, PlaceLike, PlaceReview, PlaceReviewRevision and PlaceReviewReaction around conversion dry-run, partial checkpoint, resume and rerun. It then creates a synthetic post-switch Place, Organization, Program approved/pending edition, Activity, OfferingGroup, direct/group tariffs, review/reaction and actual media bytes. It takes an actual custom-format `pg_dump`, restores it to a *second* database inside the same container and compares all public-schema table digests and counts, including grants, user/group permissions and migration state. Media files are copied outside Git and checked byte-for-byte. The source DB remains intact; restoring a pre-switch dump over new writes is deliberately outside this recovery strategy.

After the exact local content-addressed artifact is frozen, pass its metadata as the optional second argument to `run-linux-probe.sh`. The bridge verifies archive, manifest and every extracted file hash, then launches the frozen `compatible_reader.py` from the extracted standby with a clean QA04 environment. That reader checks only the named restored database over the QA04-owned Unix socket in a read-only transaction; it uses the copied synthetic media and confirms new place/program/price/review/reaction/URL data. A probe without the artifact records `compatible_standby_read: NOT_RUN` and is preliminary, not final recovery acceptance.

The raw `.dump`, Django logs and exact database output remain under the ignored `/tmp` output copied to `/root/task33-evidence/`; do not commit them or quote row data. `r1-rehearsal.json` contains aggregates/booleans only. The launcher removes the owned container/socket/media roots in `finally`; inspect `run.json` for cleanup. A killed launcher requires nonce ownership verification before manual cleanup.

The separate canonical TestCase module `catalog.testcases.test_task33_r1_acceptance` covers seven actor roles, false same-address matching, source row/URL preservation and post-switch drift. It must run with QA04 `--mode all --label catalog.testcases.test_task33_r1_acceptance` on a freshly mirrored source. No production credentials, services, deployment or backup scripts are used.
