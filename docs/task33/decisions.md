## D01. Объём и создание

Вся №33 по этапам: R1 — основа каталога; R2 — специалисты и события. Добавить место сразу открывает обычную форму. Organization необязательна, может иметь ноль филиалов и не требует физического адреса.
Обычный зарегистрированный создатель сразу управляет своим новым Place/Organization, приглашает сотрудников и связывает свои новые объекты. Проверка публикации и подтверждение бизнеса отдельно.
Волонтёр предлагает сведения, организацию, места, занятия и связи; админы проверяют. Volunteer авторство не даёт бизнес-владения.
Фиксированный лимит 10 мест убрать. Похожие объекты показывать с выбором открыть/запросить управление/объяснить отдельное создание. Не объединять по имени.

## D02. Принадлежность организации

Existing Place присоединяется с подтверждением обоих текущих владельцев. Один владелец обеих сторон подтверждает один раз. Присоединение не передаёт владение Place.
KidsMap может подтвердить информационную связь без зарегистрированных представителей; сетевые бизнес-права от этого не появляются.
Любая сторона может прекратить связь. Сохраняются Place, Activity, groups, tariffs, reviews и IDs. Сетевой доступ прекращается; последняя approved общая часть Program остаётся как местный snapshot с происхождением.
Общие контакты используются, если нет местных. После detach не копировать прежний общий телефон в Place: запросить местные контакты, карточку автоматически не скрывать.
Переезд — обычная правка адреса, без отдельного мастера. История изменений сохраняется; прежнее Event не меняет свой фактический адрес.

## D03. Сотрудники бизнеса

Приглашения сотрудников нужны. Назначает только owner. Presets и индивидуальные действия; selected_places либо all_network, явно включая будущие филиалы. Выбранные все нынешние Place не становятся all_network.
Профиль Org и общая Program — отдельные права. Manager не делегирует и не передаёт владение.
Branch creation — отдельное право. Если сотрудник создаёт филиал из Org workspace, owner Place — owner Org, created_by — сотрудник. Selected scope не расширяется автоматически.
При transfer прежняя команда приостанавливается, приглашения отменяются; новый owner выбирает, кого оставить. Волонтёры и админы KidsMap — отдельные роли, не эта команда.

## D04. Программы и публикация

Program содержит approved общие описания/переводы/categories; Activity — конкретный Place и local supplement; OfferingGroup — local age/text schedule/language/teachers; PricingPlan — группа или услуга Place.
Approved Program обновляется сразу для всех связанных активных филиалов. Local prices/groups/schedules сохраняются.
После явного сохранения сразу применяется сумма цены и расписание. Описание/адрес/контакты/фото/categories/существенные условия модерирует KidsMap. Зависимый пакет цены+условий проверяется целиком.
Approved public версия остаётся при draft/pending/rejected edits. Stale approval не перезаписывает свежие поля. Autosave ничего не публикует.

## D05. Форма и черновики

Одна форма с разделами: о месте; адрес/контакты; занятия/цены; фото/проверка. Организация, дополнительные занятия/группы/переводы по необходимости. Park/admission не требует вымышленного Activity.
Server autosave с saved_at/error; фото сохранено только после успешной загрузки. Продолжение с другого устройства. Browser-only draft отличается от server draft. Ошибка сохраняет ввод.
Макеты создаются до реализации экранов и принимаются пользователем отдельно. Нынешние tokens/components сохраняем, глобальный новый framework не добавляем.

## D06. Публичные карточки

Основной каталог — Place, один результат на филиал; внутри только matched offers. Полная страница показывает остальные предложения отдельно.
Org имеет собственную страницу и находится по названию/из филиала. Отдельного Org directory нет. У Org нет общего числового рейтинга.
Нет coordinates — остаётся в list. Нет настоящих фото — брендовая category placeholder. Общественное место может не иметь контактов: адрес/маршрут. Business нужен хотя бы phone, WhatsApp или website (допустим active inherited contact).
Общий подтверждённый venue даёт одну точку с независимыми карточками; близкие координаты не объединяют бизнесы. Фильтры применяются внутри точки.

## D07. Отзывы

Один текущий редактируемый отзыв account/target, approved версия видна до проверки нового текста/rating. Latest approved оценка known account — один вклад.
Старые повторные тексты, IDs, решения и reactions сохраняются в history; unknown/null-user не объединяются по имени/сессии. Перед включением формулы показать сравнение aggregate баллов.
Reactions относятся к версии текста: новая approved редакция имеет свой счётчик, прежние reactions не удаляются.
KidsMap проверяет отзывы; бизнес отвечает/жалуется, не approve/reject/hide чужие отзывы. Place/Activity/Specialist/Event цели и рейтинги раздельны.

## D08. Специалисты

Один профиль человека; предлагающая организация/автор не получает владение личностью. Claim проверяет KidsMap. Employment подтверждают специалист и организация; прошлые участия сохраняются.
Личные сведения и документы недоступны через Place/Org manager scope. Online не удаляет историю PracticeLocation. Public certificate выбирает специалист и одобряет KidsMap; identity/ownership evidence всегда private.

## D09. События

Один organizer: Organization либо подтверждённый самостоятельный Specialist. Venue независимо от organizer; online без выдуманного Place/coordinates. Owner venue не управляет чужим Event.
Дата/время и Asia/Baku конкретны; publication отдельно от occurrence state. Cancellation/reschedule/history не уничтожают прежние сведения; прошлое проведение не заменяется будущим под тем же ID.
Афиша: список и календарь. Desktop месяц; mobile дни+список дня. Filters сохраняются, календарь не ограничен list pagination. Past/canceled страницы доступны честно. Automatic series/registration/payment не входят.

## D10. Языки и условия

Сейчас обязательный язык новой карточки AZ, RU/EN позже. AZ fallback помечен; непереведённая оболочка не считается полноценным переводом. Locale не выбирает валюту/страну/язык занятия.
Budget filter и sorting несопоставимых prices исключены. Class schedule — text; opening hours отдельно. Unknown data явно unknown, без догадки. Conditions confirmation — явное действие, не фото.
Engineering default для пометки давности conditions — 90 дней, конфигурируемо; это не скрытие/закрытие и не подтверждение отсутствия набора.

## D11. Уведомления и выполнение

Workflow статусы/действия доступны в cabinet; важные invitations/decisions также email. Durable outbox/retry/dedupe, служебные сообщения отдельно от будущих новостных подписок.
28 отдельных этапов, один активный этап с изменениями. Новый чат читает решения, relevant architecture, status и конкретное задание; не восстанавливает всю историю диалогов.
Принятие макетов перед dependent implementation обязательно; реальный deploy отдельным поручением. Изолированная PostgreSQL/DB/cache/media/email, DJANGO_TESTING=1. Не коммитить/push/deploy автоматически.
