## Поведение и исходники

- `src/catalog/models/review_versions.py`, `models/review.py`, `models/specialist.py`: четыре типизированных семейства Place/Activity/Specialist/Event, отдельные head/revision/reaction/response модели; прежние PlaceReview/SpecialistReview PK сохранены, без GenericForeignKey. У известных авторов уникален только текущий head на target; неизвестные источники остаются отдельными.
- `src/catalog/migrations/0128_task33_review_versions.py`–`0130_task33_review_versions.py`: исходная запись становится baseline revision, sibling остаётся архивом; реакция привязана к исходной baseline revision с прежним PK. Выбор head: approved прежде остальных, затем effective `moderated_at`/`created_at` и PK. Перед PostgreSQL DDL в 0128 обработаны deferred FK события. Обратная миграция через созданную историю намеренно не предусмотрена.
- `src/catalog/services/review_versions.py`, `place_review_submission.py`, `reactions.py`: атомарная запись кандидата, optimistic CAS по revision ID, cooldown, staff-only approve/reject, approved projection до нового решения, реакция только на видимую revision. Owner может ответить или отправить приватный report, но не модерировать. Доступ повторно проверяется внутри транзакции.
- `src/catalog/services/review_retention.py`, `account_deletion.py`, `content_quality.py`, `rating_ranking.py`, `models/specialist.py`: применена действующая политика удаления/анонимизации ко всем четырём типам и реакциям; агрегаты читают только текущие approved contributions каждого типа. Общий балл Organization не вводился, новая формула ranking в production не активировалась.
- `src/catalog/controllers/typed_reviews.py`, `owner_reviews_controller.py`, `domain_admin/review_versions.py`, шаблоны `typed_reviews.html`, `includes/typed_review_link.html`, `static/css/pages/typed_reviews.css`, `urls.py`: локализованные author/public/business/staff действия и read-only история в админке; старые owner moderation endpoints закрыты.
