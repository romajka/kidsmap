## Реализация

- `src/catalog/domain_admin/business.py:BusinessEditor` и `OrganizationAdmin/ProgramAdmin/ActivityAdmin/OfferingGroupAdmin`, `src/catalog/templates/admin/catalog/business/change_form.html`: отдельные редакторы Organization, общей Program, Activity и Group. Названия/описания AZ/RU/EN, структурные parent поля только при создании, секции формы, server version fields, current/candidate diff, раздельные publication/ownership/verification подписи. Draft/submit вызывают `publication.propose`, approve — `publication.review`; структурное создание использует `create_organization` либо locked model services. После approve Activity получает `published`; Group наследует публикацию Activity, а `conditions_verified_at` показан отдельно. Activity показывает группы, число тарифов и переход к nested v2 тарифам Place; standalone Place остаётся самостоятельным объектом.
- `src/catalog/domain_admin/__init__.py:_build_sidebar_sections`, `src/catalog/domain_admin/owner.py:OrganizationGrantAdmin/OrganizationTeamInvitationAdmin`: навигация Organization/филиалы/программы/занятия/группы/сотрудники и рабочие фильтры связанных списков. Grant/invitation admin только для чтения; приглашение из Organization editor вызывает `business_team.invite` с owner ACL. Сотрудник без права владельца не редактирует Organization, даже если он platform superuser; одобрение проверяет отдельное право модератора.
- `src/catalog/services/publication.py:unpublish`, `src/catalog/domain_admin/place.py:PlaceAdmin.changeform_view/_handle_unpublish_submit`, `business.py:BusinessEditor.transition_view`: Place, Organization, Program и Activity снимаются с публикации только серверным сервисом с существующим `place.publish` reviewer ACL, lock, `content_version` и проверкой ожидающей заявки. Place action обрабатывается до обычного сохранения формы; прямой `obj.save()` путь удалён. Group не имеет отдельного publication status и следует Activity. Ready/public/verified не сведены в один статус.
