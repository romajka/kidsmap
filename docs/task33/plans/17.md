# Stage 17 workflow inbox and durable email outbox implementation plan

**Goal:** Persist workflow notifications and one email delivery intent per event/entity/version/recipient, expose a private cabinet inbox, and deliver only through an explicit local runner.

**Architecture:** Workflow services write a generic `WorkflowNotification` and matching `EmailOutbox` in the same DB transaction as the accepted transition. A unique event key provides deduplication. The outbox contains no private workflow payload; the email links to a login-protected inbox. Existing owner/business/moderation services keep all permission and version checks. The runner claims pending/retry rows, checks current invitation/access state, records bounded reason codes, and never resends a row marked sent.

**Tech stack:** Django models/views/management command, PostgreSQL isolated QA04, Django locmem email backend, existing account templates.

**Spec:** `docs/task33/prompts/17.md`, `docs/task33/decisions.md` D11, `docs/task33/architecture.md` Notifications.

**Global constraints:** Only stage17; preserve dirty WORKTREE; no production writes, real email, cron, commit/push/deploy, or stage18. Test in QA04 with `DJANGO_TESTING=1`, isolated PostgreSQL/cache/media/email. URL actions require login, current rights, CSRF POST.
