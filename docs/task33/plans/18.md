# Public details and presentation resolver Implementation Plan

**Goal:** Public Organization, Place and Activity details consume approved live data through one presentation resolver.
**Architecture:** `public_presentation.present(obj, language)` returns visible, localized, source-labelled display data without consulting pending revisions. Existing price formatter and ownership snapshots remain authoritative. SSR views/templates use the same result as card/map/SEO adapters; existing Place tracking remains untouched.
**Tech Stack:** Django/PostgreSQL, existing CSS tokens/Material Symbols, isolated QA04 and Chromium.
**Spec:** prompts/18.md, decisions D02/D04/D06/D10, accepted admin-public-03-r1.

## Constraints

Only18; preserve current dirty WORKTREE; no commit/push/deploy/production or19/20 algorithms. AZ/RU/EN and widths320/360/390/768/1024/1280/1440. No Org rating, no invented Org for standalone Place, no pending data, no live inherited Program/contacts after detach. Preserved approved local snapshot is allowed by D02.
