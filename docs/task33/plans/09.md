# Stage 09 server drafts implementation plan

**Goal:** Save incomplete, private, versioned work from any device without changing approved content.

**Spec:** [prompt 09](../prompts/09.md), [architecture](../architecture.md) (drafts/screens), decisions D04/D05.

**Scope:** Server Draft model, migration, service, CSRF JSON views, private draft photo endpoint, contract for later owner screens, account-scoped existing browser fallback. No stage10 or new owner screen integration.

1. Add failing PostgreSQL-backed API tests for incomplete create, cross-device read, duplicate retry, stale version, current ACL after revocation, live isolation, invalid payload, CSRF and private photo. Run RED in isolated QA04 harness.
2. Add Draft model with UUID ID, actor, allowed target, source/schema/draft versions, JSON payload, private photo path and save timestamp. Migration after catalog0121.
3. Add service methods for create/update/read/list, materialize with row lock and one created Place, and upload normalized photo in storage outside public MEDIA_ROOT. Check current actor and target permission on every operation, including reads; never trust a stale session grant.
4. Add JSON GET/POST Django views with CSRF, strict shape and 400/403/404/409/422 responses. Return structured errors, draft ID/version/source version/saved_at/status. Retain client input in error responses.
5. Document UI states and account/object local fallback. Update existing browser key to include account ID. Run fresh targeted tests, migration/check, privacy/transport probes, independent review and scoped diff/manifest. Report missing verification honestly.
