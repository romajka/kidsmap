# ORG-QA-01 — опубликованная организация получает устаревшую базу автосохранения

Статус OPEN; P2; высокая уверенность. Свежая локальная проверка текущего WORKTREE, не доказанная regression и не утверждение о production.

Роль: владелец организации. URL: `/ru/account/organizations/1/`. Автосохранение: `/ru/api/drafts/` и конкретный draft.

1. Владелец создаёт организацию, меняет её поля; дожидается серверного автосохранения.
2. Отправляет на проверку. Модератор одобряет; content_version становится 2.
3. Владелец открывает опубликованную организацию и меняет EN название.
4. Автосохранение возвращает HTTP 409. В той же вкладке reload восстанавливает значение из локального browser recovery.
5. В новой независимой browser context значение отсутствует. Форма сообщает source_version 2, но указанный ServerDraft имеет source_version 1.

Ожидание: новое изменение после обычной публикации сохраняется в серверный рабочий черновик на текущей базе; публичная версия меняется только после review. Факт: базовая версия формы и привязанного draft расходятся. Прямое сохранение через явную отправку проверяется отдельно; локальная копия уменьшает риск, но не обеспечивает перенос между сессиями.

Доказательства: [native autosave result](../published-recheck.result.txt), [independent session / API proof](../published-server-proof.result.txt), [screenshot](../screenshots/published-autosave-recheck-390.png). Первый harness ошибочно назвал same-tab reload PASS: это не PASS серверного сохранения; две проверки независимой сессии — FAIL.

Причина проверена по source: `src/catalog/controllers/organization_workspace.py:314–335`, `_detail_context` выбирает последний ServerDraft. Поля накладываются только при совпадении source_version, но сам draft передаётся форме без этой проверки. `organization_workspace.html:528` сочетает текущую версию организации с ID/version старого draft; `static/js/organization_workspace.js:198` отправляет их вместе. CAS корректно отклоняет запрос.

Влияние P2: обычное редактирование опубликованной организации теряет серверное автосохранение и продолжение в другой сессии; прямой потери опубликованных данных или обхода прав не доказано. Владелец области: Django workspace + frontend draft recovery; зависимость от контракта ServerDraft/publication. Следующий шаг — согласованный отдельный repair scope. Не отключать CAS и не подменять submitted candidate рабочим черновиком.
