## Причины и исправление

1. Сервер возвращал корректный 400, но шаблон не выводил ошибки name_ru/name_en/phone/whatsapp/description. Django добавлял `aria-invalid` и `aria-describedby`, хотя соответствующего текста в DOM не было. Теперь все видимые поля используют один include с error ID; сводка выводит все field/hidden/nonfield errors. Скрытые ошибки версий остаются текстом, без перехода к hidden input.
2. Общей сводки редактора не было. Добавлен `role=alert`, заголовок RU/AZ/EN, программный фокус и ссылки к полям. Tab → Enter переводит фокус к нужному полю; без JS остаются обычные ссылки. Ошибки вынесены за `<label>`, чтобы не повторять их в доступном имени поля.
3. Старый sessionStorage мог заменить более новый ввод из отклонённого POST. На bound error-response теперь приоритет у сервером возвращённых значений; они записываются в существующую локальную копию. При загрузке 400 новый ServerDraft POST не отправляется. Восстановление на обычном GET сохранено. Если storage недоступен, форма сохраняет bound input и не сообщает о сохранении.
