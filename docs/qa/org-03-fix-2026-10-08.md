## Первопричина и минимальный scope

`static/js/organization_workspace.js` удалял `kidsmap:org:create:<user>` в событии submit. Это событие не подтверждает ни отправку, ни создание. В свежем Chromium после abort настоящего POST локальная копия стала null, а повторное открытие формы восстановило пустое название. [До исправления](org-03-fix-2026-10-08/evidence/browser-red.json), [скриншот](org-03-fix-2026-10-08/screenshots/before-network-loss-390.png).

Изменены только три файла приложения:

1. `static/js/organization_workspace.js`: submit сохраняет текущие значения, включая autofill без input event; успешное подтверждение очищает только совпадающую копию текущего пользователя. Более новый текст остаётся локально.
2. `src/catalog/controllers/organization_workspace.py`: после успешного canonical create записывает одноразовое подтверждение в session; redirect содержит случайный nonce, без названий/контактов. Detail выдаёт подтверждение только после существующей ACL-проверки, при совпадении nonce, организации и пользователя. Обычный/поддельный GET его не выдаёт и не расходует; корректное подтверждение расходуется один раз.
3. `src/catalog/templates/pages/organization_workspace.html`: безопасный `json_script` с подтверждёнными полями на соответствующем detail. Без этого небольшого серверного сигнала нативный POST не позволяет браузеру надёжно отличить успешное создание от ошибки или обычного посещения кабинета.

Схема БД, canonical create/duplicate rules, request_join/confirm_join/detach, владение, ACL, consent, publication и редактор ServerDraft не менялись. CSS, тексты, изображения и другие findings не исправлялись. Дополнительно добавлены одна JS-регрессия, шесть server regressions и этот отчёт. [Diff только текущей задачи относительно входного WORKTREE](org-03-fix-2026-10-08/local.diff).

Codebase Memory использован для поиска organization_create; critical path проверен по source/route/template. Graph имеет partial template coverage и не является доказательством отсутствия ошибок.
