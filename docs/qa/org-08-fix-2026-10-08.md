## Что подтверждено и исправлено

Свежая проверка реального POST200 с MANAGER подтвердила: reset вернул EDITOR, summary осталась manager, строка появилась лишь после reload. Исторический аудит использован для scope, не как свежая проверка. [Воспроизведение](org-08-fix-2026-10-08/evidence/browser_before.json).

Первопричина — reset без updateRole и отсутствие обновления invitation list. Исправление:

- После подтверждённого POST форма сбрасывается; роль, summary, scope и показ филиалов синхронизируются.
- Pending list обновляется read-only GET существующего workspace. Из полученного серверного HTML заменяется только owner-visible invitation fragment; весь редактор и его ввод остаются на месте. Строка показывает фактически сохранённую роль и область.
- На время POST/GET действуют single-flight guard, disabled controls, aria-busy, loading text. Повторное Enter/submit не создаёт второй POST.
-400/403 сохраняют полный ввод.409 сохраняет ввод и показывает актуальную серверную строку, не переименовывая её под новую выбранную роль.
- При потерянном ответе не утверждается, что приглашение не создано. Ввод остаётся, доступна кнопка проверки списка через GET.
- Если POST200 уже получен, а чтение списка не удалось, сообщение различает успешное создание и ошибку списка. Повторное обновление списка не отправляет приглашение снова.
- Одна CSS rule для `[data-team-refresh][hidden]` обеспечивает реальное скрытие новой кнопки; общий action-button display иначе перекрывал native hidden.

[Локальный diff относительно входного WORKTREE](org-08-fix-2026-10-08/evidence/local.diff). Три существующих файла приложения, два новых тестовых файла. API/services/models/migrations, canonical invite/duplicate pending/ownership/scope/CSRF/ACL, join/confirm/detach и PO/MO не менялись. Запрос приглашения не выдаёт grant.
