# Баг-репорт: просмотр и решения модератора

16.10.2026. Сайт проверен в авторизованной пользовательской сессии только просмотром. Мутации воспроизведены отдельно на вымышленных данных. Версия production-кода отдельно не сверялась. Полный scope и ограничения — [REPORT.md](REPORT.md).

## AM-01 · P2 · Проверка отзыва теряет вход администратора

**Где:** production. Уверенность высокая. Владелец исправления: Django + admin UI.

**Шаги:** войти в `admin.kidsmap.az` → Каталог → Отзывы по кружкам → открыть отзыв → «Открыть проверку KidsMap» → раскрыть меню на открывшейся странице.

**Получилось:** переход с `admin.kidsmap.az/ru/reviews/place/target/.../` на `kidsmap.az/ru/reviews/place/target/.../`. Меню предлагает «Войти или зарегистрироваться». Административных действий на странице нет. При возврате в админку исходный вход сохраняется.

**Ожидалось:** модератор открывает текст/редакцию и принимает решение в своей авторизованной рабочей области.

**Причина:** ссылка ведёт на публичный `typed_reviews`, а `AdminHostRedirectMiddleware` переносит все не-admin маршруты на публичный домен. Разделение сессий задумано самим middleware; серверные cookie-значения не читались. Нельзя решать это бездумным расширением области cookie.

**Source:** `src/catalog/templates/admin/catalog/placereview/change_form.html:133`; `src/catalog/domain_admin/review_versions.py:38`; `src/catalog/middleware.py:53`. **Evidence:** LIVE-04 в [live-observations.json](live-observations.json); `probe.json → host_routing` (301 на отдельный публичный host, guest получает 0 candidate-блоков).

**Исправление/приёмка:** разместить административную проверку редакции в admin-origin с объектными правами. Проверить прямой вход из очереди и карточки при отсутствии публичной сессии, включая неопубликованные targets.

## AM-02 · P2 · Предпросмотр места на модерации открывает Not Found

**Где:** production и локальный стенд. Уверенность высокая. Владелец: admin UI + Django.

**Шаги:** Модерация → Места на проверке → открыть ожидающее место → Фото → «Посмотреть на сайте».

**Получилось:** новая вкладка на публичном домене с заголовком Not Found. На локальной копии публичный адрес pending-места также вернул 404.

**Ожидалось:** закрытый просмотр полной карточки до принятия решения, с явной пометкой «предпросмотр», без публикации.

**Причина:** ссылка использует обычный `obj.get_absolute_url`, без учёта статуса публикации. Сам запрет публичного доступа к pending-месту корректен; ошибочна кнопка, обещающая пригодный просмотр.

**Source:** `src/catalog/templates/admin/catalog/place/form/section_media.html:53`. **Evidence:** LIVE-05; `probe.json → pending_place_public_preview` (editor 200, public 404). В отличие от этого, специальный site-preview заявки на административном домене работает — LIVE-07.

**Исправление/приёмка:** единый защищённый admin-preview для pending/draft/опубликованного кандидата; публичный URL использовать для действительно опубликованной карточки.

## AM-03 · P2 · Ожидающие правки отзывов исчезают из очереди

**Где:** текущая LOCAL WORKTREE-копия. На реальных данных production мутацией не проверялось. Уверенность высокая. Владелец: Django.

**Шаги:** создать новый отзыв → одобрить → автор отправляет правку → открыть «Отзывы на проверке». Для сравнения оставить ещё один новый, ни разу не одобренный отзыв.

**Получилось:** новый отзыв есть, правки опубликованных отзывов нет. В изолированной базе было 4 pending-кандидата: 2 первых отзыва и 2 правки; очередь показывала только 2 первых. После массового одобрения одной первой записи в очереди осталась 1 строка, при этом pending-кандидатов по-прежнему 4.

**Ожидалось:** каждая актуальная редакция, ожидающая решения, присутствует в очереди. Старая одобренная редакция может при этом оставаться публичной.

**Причина:** proxy-очередь фильтрует `head.status='pending'`, а сервис при правке опубликованного отзыва сохраняет `head.status='approved'` и записывает pending в `candidate_revision`.

**Source:** `src/catalog/proxy_apps/catalog_moderation/admin.py:151`; `src/catalog/services/review_versions.py:183`. **Evidence:** [browser.json](browser.json), `rows[*].rows=2` для queue; `probe.json → pending_candidates / queue_after_bulk`; [локальная очередь](/home/ramin/kidsmap/output/playwright/admin-moderation-audit-2026-10-16-r1/ru-1440-queue.png).

**Исправление/приёмка:** отбирать актуальные pending-кандидаты и показывать именно отправленную редакцию. Согласовать счётчики и переходы с очередью; проверить новую запись, правку, отклонение, повторную отправку и смену решения в соседней вкладке.

## AM-04 · P1 · Массовое одобрение публикует отзыв без завершённого решения по редакции

**Где:** локально, native browser. Уверенность высокая. Владелец: Django, сверка целостности данных.

**Шаги:** открыть «Отзывы на проверке» → выбрать новый pending-отзыв → нажать массовое «Одобрить» → открыть публичные отзывы и прочитать состояние редакции.

**Получилось:** сообщение «Опубликован 1 отзыв», текст уже публичен. В БД одновременно `head.status=approved`, `is_approved=True`, **`current_revision_id=NULL`, `candidate_revision_id=1`, `candidate.status=pending`**. Запись исчезла из административной очереди. Это не просто неверный toast: состояния публикации и решения разошлись.

**Ожидалось:** одна атомарная операция одобряет конкретного кандидата, устанавливает current, очищает candidate и сохраняет автора/время решения. Повторная обработка старого кандидата должна отклоняться.

**Причина:** `approve_selected` делает прямой `QuerySet.update` старых полей. Proxy `PendingModerationAdminMixin.get_actions` заново включает legacy-действие, несмотря на ограничение нового versioned mixin. Публичная выборка допускает такую строку по старым статусам.

**Source:** `src/catalog/domain_admin/review.py:649`; `src/catalog/proxy_apps/catalog_moderation/admin.py:48`, `:149`; `src/catalog/domain_admin/review_versions.py:21`. **Evidence:** `browser.json → bulk`, `probe.json → after_browser_bulk`, `readback.json → reviews[0]`; [после массового решения](/home/ramin/kidsmap/output/playwright/admin-moderation-audit-2026-10-16-r1/bulk-after.png).

**Исправление/приёмка:** перевод массовых решений на versioned-сервис с проверкой версии каждого кандидата, корректным частичным результатом и повторным чтением публичной страницы/истории. Отдельно оценить существующие несогласованные строки read-only запросом; их наличие в production в этом аудите не установлено.

## AM-05 · P1 · «Скрыть» оставляет отзыв видимым и заменяет ожидающую правку

**Где:** локально, native browser + отдельный HTTP-сценарий. Production проверен только до подтверждения. Уверенность высокая. Владелец: Django.

**Шаги:** у одобренного отзыва открыть «Скрыть» → подтвердить → обновить публичную страницу. Дополнительный вариант: перед скрытием автор отправляет новую редакцию.

**Получилось:** сообщение «Отзыв скрыт. Его можно снова опубликовать позже», но отзыв остался в опубликованном списке. Финальная БД: `status=approved`, `is_approved=True`. Во втором варианте прежний pending-кандидат №3 с оценкой 2 заменён ссылкой на новую копию старого публичного текста №7 с оценкой 5. №3 физически остался в истории pending, но уже не является текущим кандидатом. Удаление записи не заявляется.

**Ожидалось:** отзыв действительно исчезает с публичной страницы; ожидающая авторская правка сохраняется и остаётся доступной для решения. Если по действующим правилам скрытие невозможно, нужна явная ошибка без ложного успеха и без подмены кандидата.

**Причина:** `hide_view` вызывает legacy `_toggle_review_visibility`; переопределение в `PlaceReviewAdmin` обходит защитный mixin. `save_legacy_source` трактует переход в pending как создание новой редакции, восстанавливает публичную одобренную проекцию и заменяет candidate.

**Source:** `src/catalog/domain_admin/review.py:576`, `:613`; `src/catalog/services/review_versions.py:44`; `src/catalog/domain_admin/review_versions.py:25`. **Evidence:** `probe.json → single_hide`, `controls.json → hideAlerts / hiddenTextStillPublished`, `readback.json`; [после скрытия отзыв всё ещё опубликован](/home/ramin/kidsmap/output/playwright/admin-moderation-audit-2026-10-16-r1/public-after-hide.png).

**Исправление/приёмка:** сначала определить явный контракт скрытия, затем обеспечить его отдельной атомарной операцией. Обязательно проверить одобренный отзыв без кандидата и с кандидатом; права, повтор, историю, публичную выборку и рейтинги. Не исправлять простым отключением уведомления.

## AM-06 · P2 · Кнопка открытия названа «Скрыть»

**Где:** production + локально RU. Уверенность высокая. Владелец: admin UI/localization.

**Шаги:** Каталог → Отзывы по кружкам → посмотреть действия строки.

**Получилось:** основной зелёный action ведёт на `/change/`, но подписан «Скрыть». Рядом действительно есть отдельное скрытие на `/hide/`. Также «Низкая оценка» отображается как «Ваша оценка», а «Риски» как «Поиски». Пользователь не может надёжно понять, что произойдёт при нажатии.

**Ожидалось:** «Открыть» открывает карточку, «Скрыть» обозначает скрытие. Риск/оценка названы по смыслу.

**Причина:** неверные RU msgstr: `Открыть → Скрыть`, `Низкая оценка → Ваша оценка`, `Риски → Поиски`. Это действующие строки PO, а не только устаревший браузерный cache.

**Source:** `locale/ru/LC_MESSAGES/django.po:862`, `:270`, `:1052`; `src/catalog/domain_admin/review.py:686`. **Evidence:** LIVE-03, свежая отдельная компиляция PO/MO и скриншот `ru-1440-queue.png`.

**Исправление/приёмка:** исправить смысловые переводы и проверить их потребителей в административных действиях. Не заменять строку глобально без просмотра контекстов.

## AM-07 · P3 · Устаревшая заявка предлагает «Принять» в списке

**Где:** production. Уверенность высокая. Владелец: Django + admin UI.

**Шаги:** открыть список заявок на владение → у текущей pending-заявки увидеть «Принять» → открыть «Проверить карточку».

**Получилось:** просмотр сообщает «Заявка устарела… Перед одобрением нужна новая заявка», кнопки одобрения нет. В списке эта же заявка остаётся обычной ожидающей решения и предлагает «Принять» без объяснения блокировки.

**Ожидалось:** в очереди сразу понятна причина, по которой заявка не может быть принята, и следующий разрешённый шаг. Защиту актуальности сохранять.

**Причина:** контекст preview учитывает `preview['stale']`, список/GET подтверждения используют более простой pending-путь. Точная причина устаревания этой production-заявки по версиям отдельно не исследовалась.

**Source:** `src/catalog/domain_admin/owner.py:649`, `:1176`; `src/catalog/services/admin_place_preview.py:195`. **Evidence:** LIVE-06. Это UX-несогласованность; невозможность принять устаревшие данные сама по себе не является багом.

## AM-08 · P2 · После публикации места админка сообщает, что его не существует

**Где:** локальный браузер, полный submit + подтверждение. На production кнопку публикации не нажимали. Уверенность высокая. Владелец: Django admin.

**Шаги:** Места на проверке → готовая карточка → Опубликовать → подтвердить публикацию в модальном окне.

**Получилось:** POST возвращает 302; затем сообщение «Места на проверке с ID … не существует. Возможно оно было удалено?». При этом реальный результат положительный: публичная страница 200, в БД `published`, active/public true.

**Ожидалось:** сообщение об успешной публикации и переход в обычную карточку или обратно в очередь. Объект не должен называться удалённым.

**Причина:** `_handle_publish_submit` возвращает `_place_change_url` текущего proxy-admin. Его queryset допускает только pending-места, поэтому уже опубликованный объект при следующем GET недоступен.

**Source:** `src/catalog/domain_admin/place.py:4215`, `_place_change_url:3905`; `src/catalog/proxy_apps/catalog_moderation/admin.py:112`. **Evidence:** [publish.json](publish.json), [readback.json](readback.json), [административный результат](/home/ramin/kidsmap/output/playwright/admin-moderation-audit-2026-10-16-r1/publish-result.png), [публичная карточка](/home/ramin/kidsmap/output/playwright/admin-moderation-audit-2026-10-16-r1/place-public-final.png).

**Исправление/приёмка:** после смены статуса переходить на concrete admin-change либо очередь с корректным уведомлением. Проверить публикацию, возврат на доработку и отклонение из proxy-очереди; остальные переходы здесь не воспроизводились.
