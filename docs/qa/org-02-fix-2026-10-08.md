## Первопричина и изменение

Debounce запускал несколько параллельных POST с одинаковым `expected_version`. Пока успешный ответA задерживался, сервер уже сохранялA; запросB со старой версией получал409. Позже ответA безусловно ставил «Сохранено на сервере» и очищал sessionStorage сB. После обновления загружалсяA.

Изменён **один файл приложения**: `static/js/organization_workspace.js:113`.

- В каждый момент отправляется один draft POST; промежуточные правки объединяются в последний актуальный ввод.
- Успешный ответ обновляет `draft_id/version` для следующего CAS.
- Редакция ввода и снимок полей связывают acknowledgement с конкретным текстом. «Сохранено» и удаление локальной копии разрешены только для текущей подтверждённой редакции. Дополнительно сравнивается содержимое самой локальной копии.
- Если за время запроса введён новый текст, он остаётся локально и отправляется следующим запросом с подтверждённой версией.
-409 сохраняет локальную копию и останавливает автоматическую очередь до reload; дальнейший ввод остаётся локально, конфликт не сменяется ложным «Сохранено».

Добавлен `scripts/test_organization_autosave.cjs`:6 regression/control tests на реальном editor JS в jsdom с управляемыми HTTP acknowledgements и таймером. Это DOM regression, отдельно от rendered-browser доказательств.

[Local diff от входного WORKTREE](org-02-fix-2026-10-08/local.diff). Diff включает только JS-блок редактора и новый тест; чужие изменения относительно HEAD не смешаны с этим исправлением.

**Сохранены:** backend CAS/source-version/schema-version, ACL, владельцы, request_join/confirm_join/detach, publication/candidate rules. Django services/controllers/models/migrations, HTML/CSS и тексты переводов не менялись. Автосохранение пишет только ServerDraft. Создание организации и очистка create-form storage (ORG-03), explicit submit/старый draft поверх candidate (ORG-13), другие findings не исправлялись.
