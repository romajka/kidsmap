# ORG-04 — отвязка только после обзора последствий

2026-10-08. Локальная реализация согласованного [плана совместимости](../superpowers/plans/2026-10-08-org-04-detach-compatibility.md). Сообщение пользователя «дальше» после плана принято как согласование именно ORG-04. Последовательное исполнение одним агентом; независимая проверка другим исполнителем не проводилась.

**Результат:** старые HTML/JSON входы больше не отсоединяют место. Веб-подтверждение проходит через существующие preview → согласие → серверный receipt → coordinator → canonical detach. Проверены 130 серверных тестов/проб и 176 функциональных браузерных assertions. Отдельный console gate — **FAIL: 12 событий ViewTransition**. Это не полная приёмка приложения.

## Первопричины и изменения

| Вход / проблема | Исправление |
|---|---|
| Старый HTML POST напрямую вызывал canonical detach | После прежних проверок actor/target/ownership version возвращает 302 на существующий detach-preview; связь не меняется |
| Старый JSON POST выполнял мутацию без обзора | Валидному владельцу возвращает 409 `confirmation_required` и `preview_url`; чужие права/невалидные данные сохраняют отказ |
| «Мои места» отправляли старую POST-форму | Ссылка «Отсоединить: посмотреть последствия» ведёт в существующий обзор |
| Обзор подменял право отвязки правом просмотра карточки | Только для detach применена canonical mutation authority; законный org-side owner архивной сети может отсоединить чужой приватный филиал |
| Такая законная отвязка могла потребовать раскрыть приватную карточку | Отдельная строка содержит ID/code/complete/executable/redacted; нет названия, адреса, публикационного статуса, контактов, request IDs или приватных счётчиков |
| Новый просмотр после конфликта detach вёл в подключение | Для проблемной строки detach ссылка остаётся на detach-preview |
| Две новые строки RU уходили в AZ fallback | По две необходимые записи AZ/EN/RU; прежние переводы сохранены |

Новый внутренний `detach_access` не меняет связь и не выдаёт права. Использует fresh active actor, canonical side-owner/parent locks, ownership version, deleted/target/history условия. Исполнение повторно проверяет права и snapshot. Приватный результат не расширяет общую visibility policy; connect/search/pending продолжают использовать прежнюю ACL.

Canonical `request_join`, `confirm_join`, `detach`, модели, миграции, публикация, grants и другие ownership actions не изменены. Schema JSON API не расширена полями consent/preview_id. CSS/JS приложения не менялись. Изменены 9 production source/template/locale файлов, один существующий transport test и добавлены 16 регрессий в [test_organization_detach_transport.py](../../src/catalog/testcases/test_organization_detach_transport.py).

[Полный локальный diff только ORG-04](org-04-fix-2026-10-08/local.diff) включает эти изменения и handoff-документы; чужие dirty изменения не включены.

### Совместимость JSON

Ответ старого авторизованного клиента:

```json
{"error":"confirmation_required","preview_url":"/ru/account/organizations/43/branches/74/detach-preview/"}
```

Это согласованное изменение прежнего 200-контракта. 409 не означает успешную отвязку и не требует автоматического повторения. Клиент должен открыть обзор, получить receipt и явное согласие. Внешние клиенты неизвестны и не проверялись; их обновление перед выпуском остаётся отдельной задачей. Совместимый обход согласия не добавлен.

### Исключение archived/private

Владелец сети может иметь право изменить связь и не иметь права открыть приватную карточку. Обзор сохраняет эту возможность, показывая только известный ID связи и общие последствия. Приватные количества не отображаются как нули. Ни новых business grants, ни place.view после отвязки не появляется. Историческое approved подтверждение учитывается для canonical no-op; чужой standalone private ID без такого основания не получает receipt.

В первоначальном плане перечислялись AZ/EN каталоги. Во время rendered проверки выяснилось, что новые RU msgid без собственной RU записи наследуют AZ. Поэтому добавлены также две RU записи тех же строк. Это единственное необходимое расширение файлов локализации; остальные тексты не переписывались.

- Первоначальный browser review:108 functional PASS,flow43 PASS; ручной просмотр выявил AZ fallback двух новых RU строк. После добавления RU записей финальная матрица дополнительно проверяет язык новой копии.
- Один повтор матрицы начал работу до READY стенда:5 connection-refused contexts. Сохранён [startup race](org-04-fix-2026-10-08/evidence/browser-matrix-startup-race.json); после проверки readiness полностью повторено126/126.
- Первая loading automation использовала отсутствующий global setTimeout в CLI VM. Исправлен только harness; final4/4. [Лог](org-04-fix-2026-10-08/evidence/browser-loading-harness-error.log).
- `msgfmt` обнаружил уже существующий дубль «Перед отправкой» в AZ/EN. Те же ошибки подтверждены на входных PO до изменений: [baseline-msgfmt.json](org-04-fix-2026-10-08/evidence/baseline-msgfmt.json). Каталоги не чистились в ORG-04.
