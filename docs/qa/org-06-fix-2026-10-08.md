## Исправления и причины

1. `OrganizationCreateForm` и `OrganizationCandidateForm` не задавали labels. Shared summary показывала автоматически сформированные `Name az`, `Name ru`, `Expected version`. Теперь подписи названий, описания, контактов, отдельного создания, скрытых версий и отправки получают RU/AZ/EN переводы. Общий шаблон summary и правила полей не изменены.
2. `publication.propose` возвращал технические исключения без стабильного code; editor transport показывал raw text. Пять прежних guards получили code: `publication_schema_conflict`, `publication_source_conflict`, `candidate_version_conflict`, `candidate_dependency_conflict`, `candidate_source_conflict`. Условия, порядок, raw message и отказ остались прежними. Только owner organization editor превращает code в понятный текст. Unknown validation detail не раскрывается, вместо него — локализованная общая ошибка с сохранением ввода.
3. Одного предложения обновить страницу недостаточно: обычный GET восстанавливает личный ServerDraft/sessionStorage, который может отличаться от выигравшей версии. При конфликте добавлена ссылка **«Открыть актуальные данные»** в новой вкладке (`rel=noopener`). Явный GET `?current=1` показывает сохранённый candidate/live без подстановки личного черновика и браузерной копии. Копии не удаляются; исходная вкладка с B остаётся открытой. Старые hidden versions B не заменяются актуальными автоматически. Повтор B по-прежнему409; после сравнения пользователь может вручную отправить изменения из актуальной формы.

Изменены четыре существующих файла приложения: controller, publication service (только code у пяти raises), workspace template и одна ветка editor JS. Добавлено по девять записей PO/MO для RU/AZ/EN. Новые тесты: `test_organization_form_copy.py` (9), `test_organization_current_data.cjs` (2). CSS, модель, schema/migrations, canonical join/confirm/detach и остальные findings не менялись. [Локальный diff относительно входного WORKTREE](org-06-fix-2026-10-08/evidence/local.diff).

## Что осталось вне scope

**ORG-CREATE-A11Y-01 / P2 — нет автофокуса сводки создания после400.** Роль: владелец. URL `/ru/account/organizations/create/` (также AZ/EN). Шаги: отправить create без названия, намеренно обойдя native required для серверной проверки; дождаться400; нажать Tab. Ожидание: фокус у сводки и переход к ошибке. Факт: фокус не назначен; клавиатура начинает обход с верхней навигации. Если считать, что summary уже сфокусирована, Enter может открыть главную вместо поля. Доказательство: `create-summary-focus-existing-gap-*` в [browser_matrix.json](org-06-fix-2026-10-08/evidence/browser_matrix.json). Это18 повторов одной проблемы на трёх языках и шести ширинах. Create template и create JS block не менялись в ORG-06; исправление требует отдельного scope. На скриншотах summary сфокусирована вручную для чтения — это не доказательство автофокуса.

Прежний ViewTransition: matrix43, flows14 `InvalidStateError: Transition was aborted because of invalid state. ViewTransition opt-in disabled`. Не исправлен; браузер не объявляется свободным от console errors.
