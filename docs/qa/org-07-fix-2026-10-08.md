## Первопричина и минимальное исправление

Свежий Chromium с выключенным JS подтвердил попытку GET с query keys `csrfmiddlewaretoken`, `email`, `role`, `scope`. Запрос перехвачен и прерван до сервера, значения не сохранены. Причина — отсутствие method/action у формы; JSON POST существовал только в JS. [Повтор дефекта](org-07-fix-2026-10-08/evidence/browser_before.json).

Выбран явно разрешённый finding вариант: приглашение недоступно без работающего JS. HTML теперь задаёт POST/action существующего API; email, роль, область, checkbox филиалов и submit исходно disabled. Объяснение RU/AZ/EN видно и при выключенном JS, и при ошибке загрузки workspace script. JS сначала устанавливает submit interception, затем включает помеченные controls и скрывает объяснение. Клавиатура продолжает работать через нативные controls.

API остаётся JSON-only: насильственная native отправка безопасно получает400 POST без query. Это защитный транспорт, а не рабочий HTML fallback. Canonical invite, CSRF, ownership, scope, актуальность приглашений и права не менялись. Запрос приглашения не создаёт grant. request_join/confirm_join/detach и organization_id не изменены.

[Локальный diff относительно входного WORKTREE](org-07-fix-2026-10-08/evidence/local.diff). Только два существующих файла приложения и два новых тестовых файла. CSS, серверные services/controllers, модели, migrations и translations PO/MO не менялись.
