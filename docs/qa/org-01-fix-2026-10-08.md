## Первопричина и минимальное исправление

`request_join` проверял владение одной стороной, но не доступность самого Place. Org owner мог создать pending на чужой приватный draft по ID через legacy POST или API. `_detail_context` затем выводил название, поскольку проверял только участие владельца организации. Массовый preview уже использовал более строгую видимость.

Изменены три файла приложения и добавлен один файл регрессии:

| Файл | Изменение |
|---|---|
| `src/catalog/services/organization_ownership.py:225` | Общий `join_visible_places`: существующий public-detail queryset + актуальный `place.view`; для конкретной организации сохраняет действующее согласие прямого владельца приватного места. |
| `organization_ownership.py:283,306` | Visibility gate внутри канонических `request_join` и `_confirm`, под существующими parent locks. Закрывает оба транспорта, повтор и подтверждение исторического запроса. |
| `src/catalog/services/organization_connections.py:48` | Массовый поиск/preview/execute/result переиспользуют базовый visibility resolver. Их прежние правила выбора не расширены. |
| `src/catalog/controllers/organization_workspace.py:256` | Pending отфильтрован по актуальной видимости до загрузки связанного Place; проверка участия стороны сохранена. |
| `src/catalog/testcases/test_organization_join_visibility.py` |15 регрессий: реальный сервис, ORM, HTTP с действительным CSRF и HTML кабинета, без моков ACL. |

[Только изменения этой задачи — local.diff](org-01-fix-2026-10-08/local.diff). Это diff от входного WORKTREE, включая весь новый тестовый файл; чужие изменения не входят.

**Сохранённые исключения:** прямой владелец может подключить собственный приватный черновик или предложить его другой организации. Название такого предложения видит только владелец приглашённой организации, пока согласие соответствует текущим владельцам, ownership versions и content version. Запрос только со стороны организации такой видимости не создаёт. Согласие организацииA не используется для организацииB, даже с тем же владельцем. После подтверждённой актуальной business-связи действует прежний business ACL.

**Границы правил:** pending не даёт `place.view/edit` или ownership; одни права чтения не заменяют владение стороной. Канонические request/confirm/detach, двойное согласие, ownership counters, publication/public visibility, informational moderation и существующие reviewer/volunteer исключения сохранены. Прямых новых присваиваний `organization_id` нет. Миграций, изменений моделей, CSS, JS и переводов нет.
