# Границы доказательств и исправления собственного QA harness

Приложение и существующие assertions не менялись. Raw attempts сохранены. Итоговая matrix выбирает свежие authoritative observations, а не складывает все попытки как новые тесты.

1. `matrix.result.txt`: 18 ранних sort-Escape FAIL проверяли CSS visibility до завершения transition. Свежий `public-native.result.txt` проверяет settled state, `aria-expanded`, class, focus и настоящий Escape. Ранние 18 строк исключены; это не дефект приложения.
2. Первые fixture setup попытки: неверные поля PricingPlan, quantity без количества, канонически запрещённый 0/0. Исправлен только собственный seed, новой DB; первоначально неудачные создания не считались workflow доказательством. Некорректные point пары затем специально внесены как SIMULATED legacy fixture до проверок.
3. `fixture-correction.json`: исходная диверсификация районов и связь с организацией. Изменений audited publication transitions через ORM нет. Page16 после ручной диверсификации района противоречила координатам; её native edit был правильно отклонён validation. Ранние ожидания немедленного появления нового названия исключены. Fresh согласованная запись27 прошла valid save → candidate/reload → UI moderation approval → public search/map/reload (`update-live.result.txt`).
4. Первые проверки private search ошибочно считали echo самого запроса `HIDDEN06` утечкой, первые AZ search запросы были слишком общими. Проверяются entity payloads и конкретные неопубликованные IDs/markers. После UI публикации27 это публичная запись независимо от исторического слова HIDDEN в имени; ожидание исключения27 больше неприменимо.
5. Некорректные quick locators выбирали скрытый/фоновый mobile chip на desktop, а первый filters-open trigger был скрыт. Применены реальные form-scoped mobile/desktop controls. Оставшиеся hit-test/native-click failures принадлежат PUBLIC-QA-04; они не замаскированы force click.
6. `functional.result.txt`: связанные Back/Forward/popstate и AJAX ожидания по произвольному GET/фиксированной задержке попадали в чужое незавершённое navigation. `tail.result.txt` использует новые contexts и целевой URL; 84 проверки PASS. Последующие карточки/приватные API/empty states перепроверены отдельно.
7. Native filters: mobile category делает полную навигацию и закрывает drawer; возраст требует Apply. Ранний harness не открывал drawer повторно или ожидал desktop age URL без Apply. На768 также пришлось открывать панель по фактической visibility: hidden range/desktop chip не являются native UI доказательством. `filter-step.result.txt` показывает реальные form values и запросы; итоговый `filter-settled.result.txt` ждёт целевой URL после настоящего Apply. Непроверенные переходы не получают PASS.
8. Админка имеет несколько `_publish_place` buttons и собственный HTML confirmation modal. Первые strict-locator/navigation timeouts — QA flow ошибки. `admin-resume.result.txt` нажимает кнопку в настоящем modal. Отдельные publish/unpublish и candidate approval доказаны native UI.
9. Disabled events section отвечает 410 по существующему контракту; раннее ожидание только404 исправлено в собственном harness, application assertion не менялась.
10. Specialist detail не имеет обязательного для этого сценария единственного h1. Ранний extras locator утверждал `h1.count()>0`; это необоснованное условие при проверке перехода. `navigation-proof.result.txt` проверяет реальный переход по URL после navigation и видимый title всех трёх типов сущностей. Ранние main h1 counts также выполнялись до завершения navigation. Семантика heading/SEO этим PASS не удостоверяется.
11. Native screenshot timeout 5000ms: CLI exit1 и результат Error сохранены; повтор с 15000ms дал structured result. `drive.py` исторически возвращает Python exit0 даже при CLI error — authoritative exit хранится в `command-ledger.jsonl`, не в wrapper/pipeline native_exit. CLI0 с JSON NOT RUN также не считается успешным сценарием. Ранний фильтр ссылок temporary по literal /events/ был неверен: используются канонические URLs фикстур; authoritative type-proof.result.txt читает реальные href.
12. `filter-step.js` сначала ошибочно использовал `Request.request()` в event listener вместо `Request.resourceType()`, закрывая собственную CLI session (3 CLI exit1). Исправлен только собственный observer; собственная сессия переоткрыта как module06-proof. Это QA harness error, не ошибка приложения. Другие browser sessions не закрывались.
13. Свежий tests.log включал локальные CSRF значения в failing test HTML; 10 значений отредактированы в сохранённом evidence (`redaction.json`). Output count/assertions и native exit1 сохранены.

Snapshot/evidence не служат production доказательством. Adapter Google projection/markers и SDK transport abort явно SIMULATED; реальные SDK, tiles и clustering NOT RUN.
