## 3. Реальные недостатки

### SEO-01 — P2: эквивалентные варианты пагинации получают разные SEO-сигналы

PRODUCTION: /ru/catalog/?page=2 → canonical на себя, index. /ru/catalog/?sort=new&page=2 → тот же состав страницы при сортировке по умолчанию, но canonical на первую страницу /ru/catalog/ и noindex. Внутренняя обычная пагинация уже чистая; проблема относится к лишнему параметру в альтернативном URL, а не ко всем страницам каталога.

Источник: src/catalog/context_processors.py:177–186; src/catalog/services/public_urls.py:filtered_query_string_for_path. Контроллер уже считает new значением по умолчанию: src/catalog/controllers/place_controller.py:_build_normalized_query_params. Уверенность высокая, воспроизведено HTTP. Владелец SEO/backend. Решение: единая нормализация default sort до расчёта SEO и301 на ?page=2.

### SEO-02 — P3: page=1 оставляет дополнительный200 URL

/ru/catalog/?page=1 отвечает200 и правильно канонизируется на /ru/catalog/. Поломки индексации основного каталога не обнаружено. Решение:301 на URL без page=1, включая сочетания с допустимыми фильтрами. Сохранить page>=2; не перенаправлять все страницы на первую.

### SEO-03 — P3: цепочки нормализации

Пример из экспорта: старый RU slug карточки21 + review_sort=likes →301 удаляет параметр →301 исправляет slug →200. Два перехода не являются ошибкой redirect loop. Решение: формировать окончательный локализованный путь и очищенную query одновременно, где для этого уже доступна модель. Не добавлять повторное чтение всех карточек в общий middleware без оценки стоимости.

## 4. Технический долг

Фильтры каталога сейчас noindex,follow с canonical на общий каталог. Это существующая политика, а не доказанная причина задержки7 страниц. Для ясного разделения рекомендуется оставить фильтры вне индекса и использовать canonical нормализованной фильтрованной страницы, учитывая page; canonical на отдельную SEO-посадочную допустим только при фактически эквивалентном содержимом. Не канонизировать поиск «шахматы» на страницу «все кружки» ради принудительного продвижения.

Читаемые SEO-посадочные уже существуют. Не вводить вторую конкурирующую систему /category/ или массовую замену slug. Развивать существующий /{language}/catalog/{seo_slug}/ и общий генератор публичных ссылок.

Часть ссылок блока «Часто ищут» ведёт на посадочные, которым не хватает подходящих карточек. Дополнительно проверенные /ru/catalog/kursy-dlya-detey-v-baku/ и /ru/catalog/programmirovanie-dlya-detey-baku/ отвечают200 с noindex; в sitemap их нет. Это защитное правило качества, а не ошибка canonical. В SEO-блоке предпочтительны содержательные индексируемые посадочные; прочие фильтры можно оставить как пользовательскую навигацию. Не отключать порог ради увеличения количества индексируемых URL.

## 5. Риски и границы

«Обнаружена, не проиндексирована» означает, что Google обнаружил URL, но ещё не сканировал. Причина конкретного решения Google неизвестна: authenticated URL Inspection/Crawl Stats и проверенные Googlebot access-log обращения не исследовались. Предыдущая проверка сервера не обнаружила сегодняшних5xx, но это не исключает исторические проблемы/ограничения CDN для Googlebot. Нельзя утверждать, что причиной являются только canonical или только качество.

Полноценные RU/EN переводы должны иметь self-canonical своего языка и взаимный hreflang. Непереведённый fallback не нужно выдавать за отдельную локализованную страницу. Не объединять все языки canonical на AZ.

## 6. Legacy

Старые slug, www, /az/ и публичные адреса admin — маршруты совместимости. Их редиректы сохранять. Статусы GSC могут оставаться в отчёте после исправления и повторного обхода; цель — индексируемые конечные страницы, а не ноль исключений. Удалений не предлагается.

## 8. Лучший вариант решения и конкретный scope

| Тип URL | Предлагаемое поведение |
|---|---|
| Карточка, FAQ, основная страница каталога | 200, index, self-canonical своего языка |
| page=1, default sort=new, view, чужие параметры | 301 на окончательный URL без лишних параметров |
| Каталог page>=2 без фильтров/нестандартной сортировки | 200, index, self-canonical с номером страницы |
| Поиск, комбинации фильтров, нестандартная сортировка | 200, noindex,follow, canonical нормализованной текущей комбинации; вне sitemap |
| Содержательная SEO-посадочная с достаточной выборкой | 200, index, self-canonical; hreflang и sitemap |
| Старый slug/www/admin-public | Постоянный редирект на конечный URL; по возможности один переход |

Пакет1: ограниченная нормализация URL и согласование canonical/robots. Файлы: services/public_urls.py, middleware.py, context_processors.py, views.py при необходимости объединения slug/query; targeted tests в testcases/test_seo_indexability.py и testcases/test_localized_place_seo.py. Никаких миграций/изменения существующих slug/данных, Google-настроек или широкой SEO-переписи.

Критерии: AZ/RU/EN;301 page1/defaultsort с сохранением category/q/page>=2; канонический URL после одного перехода200; страницы2+ не теряют свой canonical/index; фильтры работают и остаются noindex; next не ломается в auth; все276 sitemap URLs остаются200/self-canonical/index; чистая внутренняя пагинация и языковые ссылки. Тесты только DJANGO_TESTING=1 с изолированными DB/cache/media. После согласования и локальной проверки — отдельная выкладка и повторное HTTP-сравнение.

Пакет2: качество и связи уже существующих SEO-посадочных. Отдельно оценить смысл близких «кружки в Баку», «кружки в Азербайджане», «кружки в Баку и Азербайджане» по реальному содержимому; не склеивать только по похожему имени. Вести SEO-блок на подходящие посадочные, не создавать сотни индексируемых фильтров.

Для7 URL: выполнить live URL Inspection, посмотреть выбранный Google canonical и доступность сканирования, при успешном live test запросить индексирование; sitemap уже содержит их, поэтому исправлять их canonical сейчас оснований нет. Срок и сам факт индексации определяет Google.
